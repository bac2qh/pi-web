# Pi Web-Hosted Implementation Sessions

## 2026-07-29

- Pi Web publishes one process-local capability at `Symbol.for("pi-web.hosted-implementation-session")` with protocol `pi-web-hosted-implementation-session`, version `1`, owner `pi-web`, and a process-stable runtime ID. Compatible same-runtime hot reload invalidates/replaces only the capability record; foreign or incompatible records are preserved.
- Start and Orchestrate remain responsible for Git/worktree choice, native session identity/name/lineage, JSONL materialization, and exact kickoff. In a direct root Pi Web RPC context they submit only target ID, absolute file, exact cwd, kickoff, `start | orchestrate`, and the optional source signal. True capability absence preserves detached print; any present invalid or failing record blocks without fallback.
- Hosted registration and ordinary browser selection share Pi Web's per-session startup promise. The host validates exact ID/file/cwd, performs its final optional-signal and capability check, then synchronously subscribes, caches, publishes one wrapper, initiates RPC extension binding, and schedules the wrapper-owned kickoff. Registry publication is the ownership-transfer boundary; no source signal, target promise, or source control channel is retained afterward.
- Pi's direct idle extension API normally provides no `ctx.signal`; cancellation is honored when a signal exists and is tested at the pre-publication boundary, but SDK service/session creation itself is not signal-aware. Never fabricate source-to-target cancellation or race away from the host promise.
- Hosted kickoff acknowledgement means **scheduled**, not preflight-accepted or settled. Binding, prompt preflight, model/tool work, and rejection remain target-owned background lifecycle. Target Stop or wrapper destruction before binding completes cancels the scheduled wrapper-owned kickoff and releases its running claim; the deferred continuation checks wrapper liveness before native dispatch. After dispatch, Stop uses native abort. Source Stop cannot address either phase. A duplicate request is rejected without a second ownership acceptance, dispatch, or refresh.
- Wrapper idle cleanup reschedules while any prompt claim, compaction claim, native streaming, or native compaction remains active, then grants a full idle window after settlement.
- Hosted publication invalidates native session discovery and advances a process-global `sessions_changed` generation over the existing running-session SSE route. Initial and reconnected streams replay the current generation. The sidebar marks a generation applied only after the latest `/api/sessions` response succeeds, leaves failures retryable, and ignores older responses or generations without changing selected session, URL, or project.
- The capability rejects any request whose own keys differ from the exact six-field protocol, including environment-shaped additions, and same-runtime records require a non-empty runtime ID. Contract widening is a rejection, never ignored input.
- Hosted diagnostics contain only lifecycle stage, target ID, launch kind, and a generic bounded error class/message. Lifecycle callbacks retain only target ID and launch kind, never source signal, kickoff, cwd, session path, environment, provider data, or tool payloads.

## 2026-08-08

- Published hosted wrappers now share Pi Web's wrapper-owned strict shutdown: release closes admission, cancels an undispatched kickoff, joins started binding, aborts compaction and agent work, awaits one `session_shutdown { reason: "quit" }`, and then calls native `AgentSession.dispose()` exactly once. This closes the prior extension-cleanup gap without adopting `AgentSessionRuntime`; prepared owners that fail before publication still use bare disposal without an invented lifecycle.

## 2026-08-22

- Existing message-free targets now initialize from a valid final active-path native thinking declaration through the SDK factory option before wrapper publication. Active-branch presence distinguishes explicit `off` from absence; malformed final values are ignored, populated sessions retain native restoration, new sessions retain defaults, global thinking settings are not rewritten, and the SDK remains the sole owner of its standard message-free model/thinking append. Hosted-first and browser-first opens inherit this through the shared same-ID startup owner without widening the six-field capability request.
